# وبلاگ من

وبلاگ ایستای فارسی با محتوای مارک‌داون — بدون پایگاه‌داده، بدون سرور و با میزبانی روی [Vercel](https://vercel.com).

- محتوا فقط با فایل‌های مارک‌داون در پوشه‌ی `posts/` نوشته می‌شود.
- در زمان build، هر فایل به یک صفحه‌ی HTML مستقل تبدیل می‌شود.
- ظاهر، تایپوگرافی وزیرمتن، چیدمان راست‌به‌چپ، حالت تاریک و واکنش‌گرایی از نسخه‌ی قبلی سایت عیناً حفظ شده است.
- تاریخ‌ها در فرانت‌متر میلادی نوشته می‌شوند و در صفحه به تاریخ شمسی نمایش داده می‌شوند.

## ساختار پروژه

```text
├── posts/              ← همه‌ی نوشته‌ها (مارک‌داون)
├── public/
│   ├── css/style.css   ← استایل سایت
│   ├── js/main.js      ← جاوااسکریپت مرورگر (دکمه‌ی کپی کد)
│   └── images/         ← تصاویر نوشته‌ها
├── src/
│   ├── layout.mjs      ← قالب‌های HTML (اصلی، نوشته، ۴۰۴)
│   └── lib/            ← مارک‌داون، تاریخ شمسی، ابزارها
├── build.mjs           ← اسکریپت ساخت (خروجی: dist/)
├── server.mjs          ← سرور پیش‌نمایش محلی
├── site.config.json    ← نام سایت، توضیحات و ایمیل
└── vercel.json         ← تنظیمات استقرار روی Vercel
```

خروجی نهایی در پوشه‌ی `dist/` ساخته می‌شود و همین پوشه روی Vercel منتشر می‌شود؛ نیازی به ارسال `dist/` به گیت نیست.

## پیش‌نیازها

- [Node.js](https://nodejs.org) نسخه‌ی ۲۰ یا بالاتر

## شروع سریع

```bash
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کنید.

## دستورها

| دستور | کار |
| --- | --- |
| `npm run dev` | ساخت + پیش‌نمایش با بازساخت خودکار؛ با هر تغییر در `posts/`، `src/` یا `public/` صفحه در مرورگر تازه می‌شود |
| `npm run build` | ساخت نسخه‌ی نهایی در `dist/` |
| `npm run preview` | ساخت نسخه‌ی نهایی و سرو آن (برای بررسی خروجی production) |

## ساخت نوشته‌ی جدید

یک فایل `.md` داخل پوشه‌ی `posts/` بسازید. **نام فایل، نشانی (slug) نوشته می‌شود.** برای نمونه، فایل `my-first-post.md` در این نشانی منتشر می‌شود:

```text
/posts/my-first-post/
```

متن فایل به این شکل شروع می‌شود (frontmatter به زبان YAML):

```yaml
---
title: عنوان نوشته
date: 2026-10-05
description: خلاصه‌ای یک‌دو جمله‌ای که در فهرست صفحه‌ی اصلی و توضیحات متا (SEO) نمایش داده می‌شود.
tags: [برچسب اول, برچسب دوم]
---

متن نوشته با مارک‌داون…
```

| فیلد | الزامی | توضیح |
| --- | --- | --- |
| `title` | بله | عنوان نوشته |
| `date` | بله | تاریخ میلادی به شکل `YYYY-MM-DD`؛ در صفحه به تاریخ شمسی نمایش داده می‌شود |
| `description` | پیشنهاد می‌شود | خلاصه‌ی نوشته؛ اگر خالی باشد از ابتدای متن ساخته می‌شود |
| `tags` | اختیاری | فهرست برچسب‌ها |
| `slug` | اختیاری | نشانی سفارشی؛ پیش‌فرض همان نام فایل است |
| `draft: true` | اختیاری | نوشته‌ی نیمه‌کاره را از خروجی حذف می‌کند |

پیشنهاد می‌شود نام فایل فقط حروف انگلیسی کوچک، رقم و خط تیره باشد (مثل `git-essentials.md`)؛ اگرچه نام‌های فارسی هم کار می‌کنند.

### ترتیب نمایش

نوشته‌ها بر اساس `date` از جدیدترین به قدیمی‌ترین در صفحه‌ی اصلی و sitemap مرتب می‌شوند.

## افزودن تصویر

فایل تصویر را در پوشه‌ی `public/images/` بگذارید و در مارک‌داون با مسیر `/images/…` به آن اشاره کنید:

```markdown
![توضیح تصویر برای نابینایان و موتورهای جست‌وجو](/images/my-photo.png)
```

تصاویر به‌طور خودکار با `loading="lazy"` بارگذاری می‌شوند. توصیح تصویر (alt) را جدی بگیرید؛ هم برای دسترس‌پذیری است و هم برای سئو.

### بلوک کد

بلوک‌های کد را بین سه بک‌تیک بنویسید و زبان کد را مشخص کنید تا برجسته‌سازی سینتکس فعال شود:

````markdown
```js
const message = "سلام";
console.log(message);
```
````

- زبان‌های رایج: `js`, `ts`, `bash`, `diff`, `json`, `html`, `css`, `python` و…
- بلوک‌های کد همیشه چپ‌به‌راست (LTR) نمایش داده می‌شوند تا کد در میان متن فارسی به‌هم نریزد.
- هر بلوک کد یک دکمه‌ی «کپی» دارد.

## پیش‌نمایش محلی

```bash
npm run dev
```

سرور روی `http://localhost:3000` بالا می‌آید:

- هر تغییر در نوشته‌ها، قالب‌ها یا استایل، خودکار rebuild می‌شود.
- صفحه‌ی مرورگر بدون دست‌کاری شما تازه می‌شود.
- برای دیدن دقیقاً همان خروجی production:

```bash
npm run preview
```

## انتشار تغییرات از طریق گیت

۱. تغییرات را کامیت کنید:

```bash
git add .
git commit -m "نوشته‌ی جدید: عنوان نوشته"
git push
```

۲. همین push باعث استقرار خودکار روی Vercel می‌شود (بخش بعدی).

هر شاخه‌ی جدا نیز یک پیش‌نمایش مستقل (Preview Deployment) روی Vercel می‌گیرد؛ برای بازبینی نوشته پیش از انتشار مفید است.

## نحوه‌ی استقرار روی Vercel

۱. در [Vercel](https://vercel.com) روی **Add New → Project** بزنید و مخزن گیت را وارد کنید.
۲. Vercel تنظیمات را از `vercel.json` می‌خواند؛ نیازی به پیکربندی دستی نیست:

```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "trailingSlash": true
}
```

۳. با هر push به شاخه‌ی اصلی، Vercel دستور `npm run build` را اجرا و پوشه‌ی `dist/` را منتشر می‌کند.

چند نکته:

- **صفحه‌ی ۴۰۴:** فایل `dist/404.html` به‌طور خودکار برای مسیرهای ناموجود سرو می‌شود.
- **URLها:** هر نوشته در `/posts/<slug>/` منتشر می‌شود؛ مسیرهای بدون اسلش پایانی به شکل استاندارد هدایت (redirect) می‌شوند.
- **نشانی دامنه برای سئو:** اگر دامنه‌ی اختصاصی دارید، در Project Settings → Environment Variables متغیر `SITE_URL` را روی آن بگذارید (مثلاً `https://myblog.com`). بدون این متغیر، Vercel خودش از متغیرهای `VERCEL_URL` استفاده می‌کند و در محلی، `http://localhost:3000` فرض می‌شود. این نشانی در `sitemap.xml`، `robots.txt` و `link rel="canonical"` به کار می‌رود.
- **Node:** نسخه‌ی ۲۰ یا بالاتر (در `package.json` مشخص شده است).

## سئو و دسترس‌پذیری

در زمان build برای هر صفحه این موارد تولید می‌شود:

- عنوان و توضیحات متا برای هر نوشته
- نشانی `canonical` و تگ‌های Open Graph / Twitter Card
- داده‌ی ساخت‌یافته‌ی [JSON-LD](https://schema.org) از نوع `BlogPosting`
- `sitemap.xml` و `robots.txt`
- `<time datetime="…">` ماشین‌خوان کنار تاریخ شمسی
- ساختار یک `h1` در هر صفحه، `lang="fa" dir="rtl"` و ویژگی‌های `aria-label` مطابق نسخه‌ی اصلی سایت

## شخصی‌سازی

- نام سایت، توضیحات و ایمیل تماس: `site.config.json`
- رنگ‌ها و تایپوگرافی: `public/css/style.css` (متغیرهای CSS در ابتدای فایل)
- فهرست ناوبری: قالب مشترک در `src/layout.mjs`
