یکی از کارهایی که موقع کار با Git زیاد انجام می‌دیم، Commit زدنه. اما صرفاً اجرای `git commit` کافی نیست؛ مهمه که بدونیم چه زمانی Commit بزنیم و چطور پیام مناسبی براش بنویسیم.

### ۱. هر Commit فقط یک هدف داشته باشه

سعی کن هر Commit مربوط به یک تغییر مشخص باشه.

مثلاً این کار درست‌تره:

```bash
git add login.py
git commit -m "Add login validation"
```

به‌جای اینکه چند تغییر نامرتبط رو با هم ثبت کنی.

### ۲. پیام Commit رو درست بنویس

پیام Commit باید کوتاه، واضح و قابل فهم باشه.

چند نمونه نامناسب:

```text
update
fix
changes
test
```

نمونه‌های بهتر:

```text
Add user authentication
Fix login validation
Update README
Remove unused imports
```

با دیدن این پیام‌ها می‌شه فهمید چه تغییری در پروژه اتفاق افتاده.

### ۳. از یک ساختار مشخص استفاده کن

یکی از روش‌های رایج برای نوشتن پیام Commit، استفاده از Conventional Commits هست.

در این روش پیام‌ها ساختار مشخصی دارن:

```text
<type>: <description>
```

انواع پرکاربرد:

| Type | کاربرد |
|---|---|
| feat | اضافه کردن قابلیت جدید |
| fix | رفع باگ |
| docs | تغییر مستندات |
| style | تغییرات ظاهری کد بدون تغییر منطق |
| refactor | بازنویسی و بهبود ساختار کد |
| test | اضافه کردن یا اصلاح تست |
| chore | کارهای نگهداری پروژه |

مثلاً:

```bash
git commit -m "feat: add user registration"
git commit -m "fix: resolve login error"
git commit -m "docs: update installation guide"
```

### ۴. قبل از Commit تغییرات رو بررسی کن

یکی از عادت‌های خوب اینه که قبل از ثبت تغییرات، یک بار اون‌ها رو بررسی کنی.

برای مشاهده وضعیت فایل‌ها:

```bash
git status
```

برای مشاهده جزئیات تغییرات:

```bash
git diff
```

بعد از بررسی، فایل‌های موردنظر رو اضافه کن:

```bash
git add .
git commit -m "feat: add dark mode"
```

### ۵. Commitهای کوچک بهترن

بهتره به‌جای اینکه چند روز روی پروژه کار کنی و همه تغییرات رو با یک Commit ثبت کنی، تغییرات منطقی و مستقل رو جداگانه ثبت کنی.

مزایای این کار:

- پیدا کردن باگ‌ها راحت‌تر می‌شه.
- بررسی تاریخچه پروژه ساده‌تره.
- برگشت به تغییرات قبلی دردسر کمتری داره.
- همکاری با برنامه‌نویس‌های دیگه بهتر پیش می‌ره.

### ۶. تاریخچه Commitها رو بررسی کن

برای مشاهده تاریخچه تغییرات:

```bash
git log
```

و برای نمایش خلاصه و مرتب‌تر:

```bash
git log --oneline
```

مثلاً خروجی می‌تونه این شکلی باشه:

```text
a31f92c feat: add user registration
b82d120 fix: resolve login error
c91a450 docs: update README
```

### چند نکته مهم

- برای هر تغییر منطقی یک Commit جداگانه بساز.
- از پیام‌های مبهم مثل `update` استفاده نکن.
- پیام Commit رو با توجه به کاری که انجام دادی بنویس.
- قبل از Commit فایل‌های حساس مثل `.env` رو بررسی کن و اطلاعات محرمانه رو وارد Repository نکن.
- تغییرات آزمایشی و ناقص رو بدون بررسی روی شاخه اصلی پروژه ثبت نکن.
- از یک سبک ثابت برای نوشتن پیام‌ها استفاده کن.
