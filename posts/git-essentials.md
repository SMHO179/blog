گیت را همه یاد گرفته‌ایم، ولی هر بار که خطا می‌کنیم یادمان می‌رود که برای بیشتر اشتباه‌های رایج، راه‌حل استاندارد دارد. این نوشته، یادداشت دستورهایی است که خودم مدام به آن‌ها برمی‌گردم.

## لغو آخرین کامیت، بدون از دست دادن تغییرات

```bash
git reset --soft HEAD~1
```

تغییرات دوباره به مرحله‌ی `staged` برمی‌گردند و می‌توانیم کامیت را از نو بنویسیم.

## تاریخچه‌ی خوانا

```bash
git log --oneline --graph --decorate -15
```

## تفاوت دو نسخه‌ی یک فایل

```diff
- const retries = 1;
+ const retries = 3;
```

## دستورهایی که کم‌تر کسی می‌شناسد

| دستور | کاربرد |
| --- | --- |
| `git stash` | کنار گذاشتن موقت تغییرات |
| `git cherry-pick <hash>` | برداشتن یک کامیت مشخص از شاخه‌ای دیگر |
| `git bisect` | جست‌وجوی دودویی برای یافتن کامیت معیوب |
| `git blame -L 10,20 file` | دیدن آخرین تغییری که خطوط ۱۰ تا ۲۰ را نوشته |

> نکته: پیش از هر کار مخرب، از وضعیت فعلی یک شاخه‌ی ایمن بسازید؛ `git branch backup`. جابه‌جایی بین شاخه‌ها یک ثانیه طول می‌کشد و خیال‌تان راحت است.

## جابه‌جایی در تاریخچه

برای دیدن نسخه‌ی یک فایل در کامیت مشخص:

```bash
git show <hash>:src/index.html
```
